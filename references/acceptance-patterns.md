# Acceptance Test Patterns

验收测试不是“功能列表”，而是第三方可以重复执行并判定通过的断言。

## 1. CSV 契约

```csv
id,flow,priority,precondition,action,expected,evidence,status
```

规则：

- `id` 唯一，格式 `AT-001`；
- `flow` 使用规格中的核心流程名；
- `priority` 只能是 `P0`、`P1`、`P2`；
- `precondition` 写起始状态和测试数据；
- `action` 写一个可执行动作；
- `expected` 写可见、可判定结果；
- `evidence` 写截图、日志、导出文件、录屏或测试输出；
- `status` 只能是 `planned`、`passed`、`failed`、`blocked`、`not-applicable`。

## 2. 最低覆盖

每个 P0 流程至少：

1. 一条主成功路径；
2. 一条空或首次使用；
3. 一条失败与恢复；
4. 一条刷新/重开或持久化；
5. 一条重复操作/防重；
6. 一条非目标检查。

涉及以下能力时追加：

- 导入：格式正确、格式错误、空文件、过大数据、部分成功；
- 导出：内容完整、文件名、编码、重新导入；
- 删除：确认、取消、撤销或不可恢复警告；
- 权限：无权限、权限变化、敏感字段隐藏；
- 跨端：返回、触控、键盘、离线、断网恢复；
- 可访问性：键盘走通、焦点可见、错误可被读出。

## 3. 好的与坏的预期

| 坏预期 | 问题 | 改法 |
| --- | --- | --- |
| “体验流畅” | 无法判定 | “提交后 200ms 内显示处理中，完成后显示结果和下一步” |
| “错误处理好” | 太模糊 | “导入非法 JSON 时保留原数据，显示文件名和首个错误位置，并提供重试” |
| “响应式” | 无标准 | “375px 宽度下文章/题目切换使用底部导航，主操作按钮可触达” |
| “保存成功” | 无恢复 | “刷新后仍显示已提交答案、得分和解析” |
| “删除完成” | 无风险控制 | “删除前显示对象名和影响范围，默认焦点在取消，确认后可撤销” |

## 4. 标准状态模板

### 空状态

预置：无数据。  
动作：打开主界面。  
预期：说明为什么为空、用户下一步是什么；不显示假数据或死路。

### 加载状态

预置：操作将超过 1 秒。  
动作：触发主操作。  
预期：立即显示处理中；禁止重复提交；允许取消或说明不可取消。

### 错误状态

预置：输入无效或外部服务失败。  
动作：执行操作。  
预期：指出失败对象、原因、已保留的数据、重试方式和求助入口。

### 恢复状态

预置：处理中断、刷新或重新打开。  
动作：再次进入。  
预期：恢复到最后稳定状态；无法恢复时明确说明丢失范围和下一步。

## 5. 证据规则

- UI 行为：截图或录屏；
- 持久化：刷新前后截图 + 导出文件；
- 导入：原始输入文件 + 错误提示截图；
- 导出：导出文件 + 重新导入结果；
- 性能/超时：时间戳日志；
- 可访问性：键盘路径截图 + 焦点轨迹；
- 真机相关：真机截图；模拟器通过不能代替真机可用。
